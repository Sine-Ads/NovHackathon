Haemophilia Intelligence Radar02
The problem

The cost is not missing information. It is late recognition.

Haemophilia intelligence arrives scattered across registries, regulators, journals, HTA bodies, congresses and investor pages — the same development, in different formats, on different days.

Consider one real shape of event:

What actually happens

A competitor's gene-therapy programme completes Phase 3 enrolment.

There is no press release. There is no article.
A single field in a public registry changes from RECRUITING to ACTIVE_NOT_RECRUITING.

There is nothing to summarise —
and that is exactly when it matters most.

Why a summariser cannot help

  • It answers "what does this document say?"
  • The event is a field change, not a document
  • The same item across three sources reads as three findings
  • A promise that was never kept produces no document at all

What is actually needed

A system that already knows what it knew yesterday, and can therefore tell you what is different today — including the things that were supposed to be different and are not.

The problem03
The difference

A news dashboard reports articles. The Radar reports state transitions.

What a summariser produces — and what Citeline, Cortellis and Evaluate produce

"A recent article discusses ongoing developments in gene therapy for haemophilia B, noting that several competitor programmes are advancing through clinical stages."

Actionable?
No owner. No date. No claim you can check. Nothing a reviewer can argue with.
The incumbents
Citeline, Cortellis and Evaluate are excellent registries — they will tell you a trial's status today. None of them tells you it changed on Tuesday, who owns that, or that a promised readout is now 41 days late.

Rendered, not written

The what changed line is generated from the diff between two stored states. It is not free text from a model, so it cannot drift from what the source actually says.

Provenance or abstention

Every claim carries a source URL and an exact supporting quote. A claim that fails provenance validation is withheld — the card shows an explicit insufficient evidence state rather than a confident assertion.

An artifact, not a notification

The card carries an owner, an SLA and a lifecycle (NEW → TRIAGED → ACTIONED → CLOSED). A reading task becomes a review-and-approve task, already assembled.

Three documents collapse into one event. Deduplication happens before a human ever sees it.

Why a URI flag, not a convention

Phase 2 opens Phase 1's database as mode=ro. A stray write raises instead of silently corrupting.

In a system whose entire value is provenance, a bug in the reasoning layer must not be able to alter the evidence it reasons over. A team convention holds until someone is in a hurry at 2 a.m.

Retrieval is four stages, not one

BM25 catches exact identifiers — NCT06550882, a sponsor's legal name — that embeddings blur. Vectors catch paraphrase BM25 misses. Fusion uses ranks only, so two incomparable scales need no tuning.

Reality check07
The Expectation Ledger  ·  Designed  schema frozen

A promised readout is not news.
It is a dated obligation.

Every system in this space treats "primary completion estimated October 2026" as text to be indexed.

It is not text. It is a row in a ledger — with a due date, an owner, and a quote that proves somebody said it on the record.

Then one of two things happens — and the second one is the whole point.

Every single one is an estimate — a promise, not a fact. Among them: NCT07653139 (Novo Nordisk, 26 Oct), NCT06738485 (CSL Behring, 26 Oct), NCT06550882 (Takeda, 30 Sep).

The system already half-recognises this

# evidence.py:100 — trials held recency-neutral because
# ClinicalTrials.gov stores a date the study has not reached
if date_class not in ("publication", "filing"):
    return 1.00

That guard is the detector. It identifies exactly the records carrying a future date — and then discards the information. The Ledger is what that branch should feed.

Absence is what a model will confabulate

So the Ledger never asks one. Every scheduled probe is written to watch_probe whether it matches or not. The log is the evidence.

The claim is not "we believe nothing happened". The claim is "we ran 63 searches on these dates against these sources and found nothing" — and a reviewer can open it.

Why this is unusually defensible

  • A reviewer can only disagree by naming a source the probe did not cover — which is a productive argument, and exactly what the calibration loop absorbs
  • A completion date that slips twice is itself a signal. Supersession keeps the history rather than overwriting it
No article is ever written about a readout that did not happen.
Silence signals10
Honesty engineering  ·  Built

The refusal is a feature, and it is enforced in code rather than asked for in a prompt

1 · The gate runs before generation

With no evidence, evidence below MIN_EVIDENCE, or nothing but stubs, no model is called at all. A templated reply names what was missing.

A model asked to judge its own confidence is its own auditor, and it fails in one direction: it under-refuses, exactly when the corpus is thinnest.

supported every claim traces to an excerpt or exact count
inferred synthesised; no single excerpt says it
insufficient the corpus cannot support an answer

2 · Numbers never come from the model

Top-k retrieval sees eight documents and physically cannot answer "how many trials are recruiting".

So the model names a whitelisted query from a fixed registry and supplies arguments. It never writes SQL and never sees a connection.

A generated query can be plausible and wrong — a missing DISTINCT, a silently dropped NULL — returning a confident number nobody can audit. In a regulated setting a wrong number is worse than a refusal.

3 · Self-report can only lower

After generation, a supported claim with no citations — or citing records that were never retrieved — is demoted.

The asymmetry closes the last hole: a model may admit it is synthesising, and that is honoured. The reverse claim is not.

The reason string on every piece of evidence — "matched on both keyword (#3) and meaning (#1, similarity 0.87)" — is assembled deterministically from the scoring fields. No model writes it, so it cannot be fabricated.

Three of the fifteen golden questions must be refused. Abstention recall gates the suite's exit code — answering one of them fails the run even if every other answer is right.

Thresholds calibrated, not picked

With completeness capped at 1.00 and recency at 1.10, a never-changed record tops out at 1.07. So HIGH_THRESHOLD = 1.02 — any higher and the High band would be unreachable until a second ingestion run.

An empty tier is not a useful one. The same completeness and recency functions drive evidence ranking, so a record cannot be urgent here and unimportant there.

RESULTS TABLE
per-category pass rate + abstention recall
from scripts/run_eval.py

Abstention recall gates the exit code

It is reported separately from accuracy, and a recall below 1.0 fails the run. A system that answers a question it cannot support has failed, regardless of how many other answers were right.

What we deliberately do not claim to have measured

  • Extraction precision/recall, dedup cluster purity, diff correctness — the single-backfill corpus produces no diffs and no duplicate clusters to score
  • Precision@10 before vs after calibration — feedback is captured, the re-weighting loop is not yet wired
Expected values are corpus-specific constants. Re-ingesting breaks the suite loudly rather than letting it silently pass — which is the point.

Business impact  ·  Partial  illustrative model

What earlier recognition is worth, with the arithmetic shown

The decisions that change

  • An HTA rejection in a reference market, recognised ten days earlier, gives Market Access a response window before follow-on national assessments anchor to it
  • A competitor readout that slips is a planning input available nowhere else — today nobody notices it at all, because no document is published when a date is missed
  • A label change caught at filing rather than at approval moves the comparative-evidence conversation upstream of the launch plan

Why we are not quoting a currency figure

Converting these into money needs internal cost and portfolio-value inputs we do not have and would have to invent. We would rather show a model you can argue with than a number you cannot check.

Time saved — the weaker half of the case

What we need from you — and what we are not claiming

What we would need from Novo Nordisk

  • One or two stakeholders per function for two short calibration sessions — the feedback loop is only demonstrable against real reviewer judgement
  • Confirmation of which functions are routing targets, and whether Safety/PV is a routed queue or read-only visibility
  • Urgency definitions and SLA expectations per function, so scoring is anchored to real practice rather than assumed
  • Priority geographies for HTA and regulatory weighting
  • Sources to add to, or exclude from, the allowlist
  • Guidance on phrasing competitive impact, given the prototype references Novo Nordisk assets only from public information

The three things we are not claiming

  • The Expectation Ledger has never run. The 134 is a live query against ClinicalTrials.gov, not our output
  • No real diff has occurred yet — the corpus is a single backfill
  • The calibration improvement is unmeasured; feedback is captured, the re-weighting loop is not wired
